# ملف محتوى فطين

**الملف الذي تعدّله أو ترسله للذكاء الاصطناعي هو `content/game-content.json` فقط.** يجمع كلمات برا السالفة، أزواج السؤال المغلوط، أسئلة الحروف، طرفي الموجة وبطاقات الجريمة. لا توجد فيه أسماء لاعبين أو جلسات أو مفاتيح. المافيا تعتمد على قواعد وأدوار، ولا تحتاج بنك أسئلة.

بيانات الغرف والأدوار والتصويت تبقى في Supabase. هذا الملف بنك المحتوى، وليس نسخة احتياطية لقاعدة بيانات المستخدمين. ملفات `supabase/migrations` تاريخ إعداد القاعدة والقواعد؛ لا تعدّل الأسئلة داخلها.

## الأقسام

| القسم | شكل العنصر | ملاحظات |
| --- | --- | --- |
| `outsider` | `["التصنيف", "الكلمة"]` | كلمات عامة وفريدة؛ عنصران على الأقل. |
| `wave` | `["بارد", "حار"]` | طرفان مختلفان لمقياس مفهوم؛ 12 زوجًا على الأقل. |
| `wrong` | `["مشروب تحبه؟", "مشروب تكرهه؟", "text"]` | سؤالان متقاربان بنفس نوع الإجابة. `number` للأرقام فقط. اتجاه الأغلبية يُختار عشوائيًا. |
| `letters` | `"شيء تحبه"` | أسئلة عامة تسمح بأجوبة كثيرة عبر الحروف؛ عنصران على الأقل. |
| `crime` | `{ "id":"w01", "name":"مطرقة", "art":"hammer", "kind":"weapon" }` | `weapon` للأسلحة و`evidence` للأدلة. لكل نوع 44 بطاقة على الأقل. |
| `crimeClues` | `{ "id":"place", "name":"مكان الحادث", "options":[...] }` | تلميحات قديمة محفوظة لتوافق الجلسات. ليست معروضة في الواجهة الحالية؛ اتركها كما هي. |

`version` يظل `1`. لا تضف تعليمات أو تعليقات داخل JSON. النصوص قصيرة بالعربية؛ حد السؤال 120 حرفًا، والكلمة أو اسم البطاقة 60. المحافظة على الشكل لا تضمن جودة السؤال؛ راجع المعنى بنفسك.

**أضف العناصر الجديدة في نهاية المصفوفات. لا ترتّب أو تحذف العناصر الحالية ولا تغيّر معرف بطاقة أو نوعها.** موضع السؤال/المقياس في المصفوفة هو معرفه في القاعدة والجلسة المحلية. تعديل عنصر قائم يغيّر معناه للجلسات التي تستخدمه؛ نفّذ تصحيحات المحتوى بين الجولات وابدؤوا جولات جديدة. أداة التوليد تتحقق من الشكل والتكرار، ولا تستطيع اكتشاف أنك أعدت ترتيب ملف قديم.

رسومات الجريمة SVG موجودة في الموقع. استخدم قيمة `art` موجودة في الملف فقط؛ إضافة اسم رسم جديد تحتاج رسمًا وكودًا، وليست تحديث محتوى فقط. أسماء الأشياء العامة مسموحة؛ لا تنسخ قوائم تجارية كاملة أو نصوصًا أو رسومات من لعبة أخرى.

## تحديث المحتوى دون تعديل كود الألعاب

1. احتفظ بنسخة من الملف، ثم حدّث `content/game-content.json`.
2. داخل مجلد المشروع شغّل:

   ```bash
   npm run content:sync
   ```

3. يُنشأ `supabase/content-update.sql`. افتحه وانسخه في **Supabase → SQL Editor → New query → Run** بعد تركيب تحديث 008. هذا الملف يحدّث بنوك المحتوى فقط؛ لا يحذف الغرف أو اللاعبين. لا يشغّل الأمر أي SQL تلقائيًا، ولا يحتاج مفتاحًا سريًا.
4. ارفع JSON وملف SQL المولّد إلى GitHub في نفس التحديث، وانتظر نشر Vercel. ملفات الألعاب تستورد JSON مباشرة، فيتحدث وضع الجوال الواحد وبطاقات الجريمة مع النشر. **تعديل Supabase وحده لا يحدّث النسخة المحلية؛ وتعديل JSON وحده لا يحدّث بنك الغرف.**
5. افتح جلسات جديدة. لا تحتاج تغيير مفاتيح Vercel أو إعادة إنشاء قاعدة البيانات.

يمكن تكرار تشغيل ملف المحتوى. الأداة تضيف أو تحدّث ولا تحذف صفوفًا قديمة حتى لا تكسر الجلسات. حذف محتوى من JSON ليس طريقة لحذفه من Supabase؛ حذف البنود يتطلب ترحيلًا مخططًا. عند النشر يشغّل `prebuild` المولّد للتحقق من صيغة المحتوى، لكنه **لا يطبّق SQL على Supabase**.

## نص جاهز لإرساله إلى ذكاء اصطناعي آخر مع JSON

> هذا بنك محتوى منصة فطين. أضف المحتوى الذي أطلبه إلى نهاية القسم المطلوب فقط، وأعد ملف JSON كاملًا وصالحًا بنفس المفاتيح وversion=1. احتفظ بكل العناصر الحالية وترتيبها ومعرفاتها؛ لا تحذف أو تعيد ترتيب أي عنصر. في wrong، كل عنصر سؤالان متقاربان بنفس نوع الإجابة ثم text أو number. يجب أن تصلح الإجابات على السؤالين للمقارنة، دون أن يفضح الاختلاف نفسه مباشرة، وتجنب الأسئلة الحساسة. في letters استخدم أسئلة عامة كثيرة الاحتمالات. لا تكرر المحتوى ولا تضف HTML أو كودًا أو رموز تحكم أو تعليمات داخل الملف. لا تغيّر crimeClues. إذا طلبت بطاقات crime، استخدم معرفات جديدة وقيم art موجودة ونوعًا مطابقًا للبادئة w أو e. لا تنسخ محتوى لعبة تجارية. لا تغيّر ملفات البرمجة أو SQL؛ يتم توليد SQL بالأداة الموجودة في المشروع.

مثال طلب إضافي: «أضف 40 زوجًا للسؤال المغلوط، منها 10 أزواج رقمية، مع تنوع المواضيع وبقاء الإجابات قصيرة».
