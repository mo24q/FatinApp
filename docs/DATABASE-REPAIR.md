# إصلاح قاعدة فطين — 009

## متى تحتاجه؟

إذا نجح تشغيل 008 لكن إنشاء الغرف يفشل برسالة عن `private.outsider_action_v2` أو `private.game_action_v1` أو `public.crime_action`، فهناك أجزاء من تأسيس 002 و003 غير موجودة. تثبيت 008 وحده لا يستعيد هذه الأجزاء. هذا ما ظهر في فحص الموقع المنشور في ٢٥ أكتوبر ٢٠٢٦؛ ملفات الموقع على GitHub تطابق نسخة الصقل v8.

## الخطوات للموقع الحالي

1. افتح مشروع **Supabase نفسه المرتبط بمتغيرات Vercel** ثم **SQL Editor → New query**.
2. انسخ كامل `supabase/migrations/009_foundation_repair.sql` وشغّله بزر **Run**. الملف المنفصل `fatin-database-repair-009.sql` مطابق له؛ استخدم أحدهما فقط.
3. انتظر رسالة النجاح ثم حدّث صفحة فطين وأنشئ غرفة جديدة.

لا تحتاج إعادة نشر Vercel أو تغيير المفاتيح لهذا الإصلاح. رفع ملف SQL إلى GitHub يحفظ نسخة منه فقط؛ لا يشغّله داخل Supabase تلقائيًا. يمكن رفع محتويات حزمة `fatin-database-repair-update.zip` إلى جذر GitHub لحفظ الإصلاح وتعليماته.

الملف يحتاج تأسيس 001 الموجود بالفعل. يعيد تعريف الدوال الأساسية بأسمائها الصحيحة مباشرة، ويضيف الأعمدة والجداول الناقصة، ثم يعيد تطبيق آخر قواعد الألعاب الست وصلاحياتها. لا يغيّر الأدوار أو الأصوات أو الإجابات في الجولات القائمة ولا يستبدل المحتوى المخصص. يضيف العناصر الافتراضية ذات المعرّفات الناقصة فقط. يعمل في معاملة واحدة ويمكن تكراره.

لا تعِد تشغيل 001 على قاعدة موجودة، ولا تشغّل 002 و003 منفردين فوق هذه الحالة؛ ترحيل أسمائهما القديم قد ينقل دالة حديثة إلى اسم غير صحيح. استخدم ملف 009 كاملًا.

قاعدة جديدة تمامًا: شغّل 001 إلى 009 بالترتيب، ثم `supabase/content-update.sql`، واتبع إعداد Auth وRealtime في README. إذا ظهر `FATIN_BASE_MISSING` فتوقف وتحقق من اختيار مشروع Supabase الصحيح؛ 009 لا ينشئ قاعدة من الصفر.

## التحقق وحدوده

أُعيد إنتاج العطل في قاعدة معزولة بتطبيق 001 ثم 008 فقط. بعد 009 نجح إنشاء الغرف والانضمام وبدء الألعاب الست، مع رفض وصول غير الأعضاء ومنع استدعاء الدوال الخاصة. جُرّب أيضًا الإصلاح بعد 001 و002 و003 و008، وتكراره مرتين مع جولات نشطة ومحتوى مخصص؛ تطابقت البيانات قبل التكرار وبعده.

هذا تحقق SQL محلي على PostgreSQL عبر PGlite. لم يُطبّق الملف على حساب Supabase من هذه الجلسة. لم يكتمل اختبار جولات أونلاين أو Realtime على الموقع المنشور لأن إنشاء الغرف كان يفشل قبل الإصلاح. بعد تطبيقه يلزم إعادة الفحص المباشر، ثم تجربة أجهزة فعلية قبل إعلان الجاهزية.

## للمطور

لتوليد 009 بعد تعديل مصادره: شغّل `node scripts/prepare-readiness-upgrade.mjs` ثم `node scripts/prepare-foundation-repair.mjs`. اختبارات الاسترجاع في `tests/foundation-repair.test.mjs`، وتشغيل جميع اختبارات القواعد عبر `npm test`. بنك المحتوى المستقل لا يزال `content/game-content.json` كما في [دليل المحتوى](CONTENT.md).
