# نفس الموجة — فطين

اللعبة الرابعة متاحة في `/wave`، ونسخة الجهاز الواحد في `/wave/local`. تدعم ٢–١٢ لاعبًا، بنسخة تعاونية: كل المشاركين يجمعون نقاطًا مشتركة. الفكرة العامة للتلميح بين مفهومين معروفة في ألعاب التوافق مثل [Wavelength](https://www.wavelength.zone/). هذه نسخة فطين بنصوص ورسوم ومؤشر وقواعد متوسط ونقاط مستقلة؛ لا تتضمن بطاقات تجارية أو صورًا من اللعبة الأصلية.

## طريقة اللعب

1. اختاروا ٤ أو ٦ أو ٨ أو ١٢ جولة. صاحب التلميح الأول يُختار عشوائيًا، ثم يتناوب اللاعبون بالترتيب. لا تُكرر بطاقة المفاهيم داخل نفس اللعبة؛ البنك يضم ٤٠ زوجًا.
2. صاحب التلميح وحده يرى الهدف بين صفر ومئة. يكتب مثالًا من حرفين إلى ٨٠ حرفًا، دون أرقام أو كلمات الطرفين أو وصف رقمي للموقع. الأرقام ورموز التحكم ممنوعة برمجيًا؛ صلاحية معنى التلميح مسؤولية اللاعبين.
3. البقية يناقشون التلميح، ثم يثبت كل شخص تخمينه. صاحب التلميح لا يخمّن ولا يقدم توجيهات إضافية. التخمين المثبت لا يتغير ولا يظهر للآخرين قبل النتيجة.
4. عند اكتمال التخمينات تُكشف النتيجة تلقائيًا. تخمين الفريق هو المتوسط الحسابي للتخمينات المثبتة، مقربًا لأقرب عدد صحيح. يظهر الهدف ومتوسط الفريق وتخمين كل مشارك.
5. فرق ٤ أو أقل يمنح ٤ نقاط، وحتى ٩ يمنح ٣، وحتى ١٦ يمنح نقطتين، وحتى ٢٤ يمنح نقطة؛ وما يزيد دون نقاط. الحد الأعلى ٤ × عدد الجولات. المضيف يبدأ الجولة التالية بعد الاطلاع على النتيجة؛ النهاية تعرض الحصيلة وسجل الجولات، ويمكن إعادة اللعب.

المؤشر ثابت الاتجاه: الطرف الأيسر صفر والطرف الأيمن مئة، حتى مع واجهة RTL. يدعم السحب واللمس ومفاتيح الاتجاه عبر حقل مدى أصلي. صفحة اللعبة تعرض مثالًا تفاعليًا للتجربة قبل إنشاء غرفة.

## المؤقت والانقطاع

المؤقت مغلق افتراضيًا لإتاحة النقاش وتمرير الجوال براحة. يستطيع المضيف تشغيله أو إلغاءه أو إيقافه مؤقتًا أو استئنافه أو إعادة ضبطه وتغيير مدته بين ١٥ و٩٠٠ ثانية. عند انتهاء الوقت تُحسب التخمينات المثبتة فقط. إذا لم يخمّن أحد، تبقى المرحلة مفتوحة حتى يوجد تخمين؛ لا نختلق تخمينًا بديلًا. يمكن للمضيف تأكيد كشف مبكر إذا تعذّر على بقية اللاعبين الإكمال، بشرط وجود تخمين واحد على الأقل.

تعالج الغرف انتهاء الوقت عند طلب الحالة التالي، مع تحديث دوري كل ٥ ثوانٍ أثناء ظهور الصفحة، وبمساعدة Realtime عند تغيّر اللعبة. لا يوجد خادم دائم إضافي أو مهمة خلفية. لذلك إذا غادر الجميع، تُطبق النتيجة عند العودة. قد يصل تخمين قبل أول طلب يحسم الوقت المنتهي. إعادة الاتصال بنفس المتصفح تستعيد المقعد والحالة. يمكن استلام الاستضافة بعد غياب المضيف ٦٠ ثانية؛ هذا لا يمنح الهدف السري للمضيف الجديد.

لا ينضم لاعب جديد أو يغادر مقعدًا أثناء اللعبة، بما فيها شاشة نتيجة الجولة الوسيطة. إدارة المشاركين متاحة في اللوبي أو بعد اكتمال كل الجولات. يستطيع المضيف إلغاء اللعبة للعودة للوبي؛ يمسح الإلغاء مجموع النقاط ولا يكشف الهدف الحالي. إذا غاب صاحب التلميح، انتظروا عودته أو ألغوا اللعبة لإعادة تنظيمها.

## الخصوصية والتخزين

- الغرف: بيانات اللعبة في `private.wave_sessions`، وبنك المفاهيم في `private.wave_pairs`، مع RLS وإلغاء صلاحيات الوصول المباشر. `wave_action` يتحقق من جلسة الضيف والعضوية والجولة والمرحلة وصلاحيات الأفعال، ويقفل الغرفة لتسلسل الطلبات المتزامنة.
- الهدف الحالي لا يدخل في الحالة العامة أو Realtime أو ملفات المتصفح غير المصرح لها. طلب `secret` يرده فقط لصاحب التلميح أثناء مرحلة التلميح. المضيف لا يراه إذا لم يكن صاحب الدور. نتائج الجولات السابقة تصبح عامة بعد كشفها، ولا تحتوي على هدف الجولة التالية.
- قبل الكشف، يعود التخمين الخاص بالطالب فقط، مع علامات إنجاز المشاركين دون قيمهم. حساب المتوسط والنقاط على الخادم؛ لا يعتمد على قيمة نقاط مرسلة من العميل.
- Realtime يستخدم `public.room_events` الموجود مسبقًا، ويحمل رقم تحديث فقط. لا تضف الجداول الخاصة إلى النشر أو إلى Exposed schemas.
- الجوال الواحد: بيانات الجلسة كلها في `sessionStorage` حتى ٢٤ ساعة. هذه خصوصية بالتناوب والثقة، وليست عزلًا أمنيًا بين أشخاص يملكون الجهاز نفسه. الهدف والتخمين يُخفيان عند فقد تركيز النافذة أو مغادرة الصفحة، وقبل تمرير الجهاز. إغلاق التبويب قد يفقد الجلسة.
- لا تحتاج نموذج ذكاء اصطناعي أو مفاتيح جديدة أو مكتبات إضافية. المفاهيم المحلية في `src/lib/wave-game.ts`، ونفس البنك مزروع في SQL؛ لتوسيع البنك للطريقتين حدّث الموضعين مع الحفاظ على المعرفات.

## تركيب التحديث على موقع فطين الحالي

يفترض التحديث أن ملفات المافيا وترحيلات 001–004 السابقة موجودة:

1. افتح **Supabase → SQL Editor → New query** والصق كامل `supabase/migrations/005_same_wave.sql` ثم **Run**. الملف نفسه مرفق باسم `fatin-wave-upgrade.sql`، ويمكن إعادة تشغيله.
2. فك `fatin-wave-update.zip` وارفع محتوياته إلى جذر **FatinApp**، مع استبدال الملفات المطابقة والحفاظ على المجلدات. ارفع الملفات نفسها، وليس ZIP أو مجلدًا إضافيًا حول المشروع.
3. احفظ التغيير في الفرع المرتبط بـVercel، وانتظر النشر. صفحة اللعبة `/wave` وبطاقتها في الرئيسية.

إن لم تركب المافيا السابقة بعد، استخدم ملفات المشروع الكاملة `fatin-project-v5.zip` وشغّل 004 ثم 005 بعد ترحيلاتك السابقة. **لا تعِد تشغيل 001 على قاعدة قائمة.** للمشروع الجديد تمامًا، شغّل 001 ثم 002 ثم 003 ثم 004 ثم 005 بالترتيب. لا تُعد تشغيل 004 بعد 005؛ كل إصدار أحدث يحدّث موزّع الانضمام العام ليشمل الألعاب السابقة.

لا تغيّر إعدادات Vercel أو المفاتيح إذا كانت الغرف تعمل حاليًا. للتطوير المحلي استخدم Node.js 24 ثم `npm ci` و`npm run dev` مع متغيرات Supabase الموجودة في README. نسخة الجوال الواحد لا تحتاج قاعدة بيانات بعد تحميل التطبيق؛ لم تُضف خدمة تضمن فتحه دون إنترنت.

## حالة التحقق

لم تُشغّل اختبارات أو بناء أو تجربة متصفح لهذه الإضافة، التزامًا بتفضيل المستخدم. لم يُطبق SQL على Supabase الفعلي ولم تُرفع الملفات إلى GitHub أو Vercel في هذه الجلسة. الحزمة مصدر جاهز للتركيب؛ نجاح البناء والتشغيل الفعلي لم يُتحقق منه هنا.
