# نسخة تجربة فطين — ٢٢ أكتوبر ٢٠٢٦

تحديث ٢٥ أكتوبر: أظهر فحص الموقع المنشور أن بعض دوال التأسيس غير موجودة رغم تطبيق 008. **استخدم [إصلاح 009](DATABASE-REPAIR.md) للموقع الحالي**. التعليمات التالية تسجل إصدار v8 السابق؛ رفع ملفات الموقع نفسه كان صحيحًا، ولا يلزم تكراره لإصلاح قاعدة البيانات.

هذه حزمة صقل للألعاب الست الحالية. لا تضيف اشتراكات أو ألعابًا جديدة. المصدر المرجعي للمقارنة هو `mo24q/FatinApp` عند الالتزام `a8ad2a38d0fd05756655bf2a7457c4617642e262`.

## تحديث موقعك الحالي

1. في Supabase افتح **SQL Editor → New query**. للموقع الحالي شغّل كامل `supabase/migrations/009_foundation_repair.sql` حسب [دليل الإصلاح](DATABASE-REPAIR.md). التحديث السابق 008 يحتاج 001 و002 و003؛ وجود الجريمة المغلقة في واجهة الموقع لا يؤكد تطبيق هذه الملفات في قاعدة البيانات.
2. انتظر نجاح SQL، ثم ارفع **محتويات** `fatin-readiness-update.zip` إلى جذر مستودعك مع استبدال الملفات المطابقة، بحيث يبقى `package.json` في الجذر. الحزمة الكاملة `fatin-project-v8.zip` بديل لمن يريد نسخة المشروع كلها. لا ترفع ملف ZIP نفسه إلى المستودع، ولا تضع المشروع داخل مجلد إضافي.
3. احذف `src/lib/party-content.json` القديم إن بقي عندك؛ المحتوى المعتمد هو `content/game-content.json`. ملفا التعليمات القديمان `MAFIA-UPDATE.txt` و`UPDATE-007.txt` ليسا تعليمات هذا الإصدار.
4. انتظر نشر Vercel المعتاد من `main`. لا تغيّر رابط Supabase أو المفتاح العام. إعدادات المشروع: Next.js، وNode.js 24.x، وتثبيت `npm ci` وبناء `npm run build`، ومجلد إخراج Next الافتراضي. متغير `FATIN_BUILD_DIR` مخصص للفحص المحلي؛ لا تضفه إلى Vercel.
5. افتح الموقع بعد النشر وابدأ غرفًا جديدة للتجربة. تحديث 008 يحافظ على الغرف والأدوار والإجابات الموجودة، ولا يعيد كتابة أسئلتك المخصصة. لا تعِد تشغيل ملفات الترقية القديمة منفردة فوق الإصدار الجديد.

قاعدة جديدة تمامًا: شغّل ملفات `supabase/migrations` من 001 إلى 008 بالترتيب، ثم `supabase/content-update.sql`، وفعّل دخول الضيوف وRealtime وفق README. قاعدة موجودة: لا تحتاج تشغيل `content-update.sql` لهذا الصقل إلا إذا كنت تحدّث المحتوى أيضًا.

لم تُطبَّق ملفات SQL على حسابك ولم تُنشر الحزمة إلى GitHub أو Vercel من جلسة الفحص. لا توجد مفاتيح سرية أو بيانات غرف فعلية في الحزمة.

## ما تغير

- إصلاح خطأ صياغة في تعريف دوال المافيا كان يمنع تثبيت 004 و007 على قاعدة جديدة.
- إصلاح تعارض اسم متغير SQL الذي كان يعطّل التصويت في السؤال المغلوط واستخدام الحروف أونلاين.
- منع تخمين متأخر في نفس الموجة من دخول المتوسط بعد انتهاء الوقت مع وجود تخمينات مثبتة. إذا لم يخمّن أحد، يبقى انتظار أول تخمين كما توضّح الواجهة.
- تحسين تباين غطاء الدور في ليل المافيا ليبقى مقروءًا على الجوال.
- رفض مزيد من حالات الحفظ المحلي التالفة في المافيا والسؤال المغلوط، بدل استعادتها وإظهار شاشة معطلة.
- إصلاح تشغيل اختبارات TypeScript وJSON المحلية، وتوسيع الاختبارات لتشمل قواعد الألعاب الست، الخصوصية، الترقية، وأفعال المتصفح.
- بيانات ترتيب النقاط تعرض حقول النتيجة المطلوبة فقط.

## تجربة قصيرة مع الناس بعد النشر

ابدؤوا بأربعة أجهزة ومتصفحات مستقلة؛ استخدموا خامسًا للمافيا، وسادسًا عند اختيار راوي بشري. تأكدوا من أن جميع الأجهزة تعرض الغرفة نفسها، وأن الدور لا يظهر إلا لصاحبه، ثم أكملوا جولة وأعيدوها. افصلوا الإنترنت عن جهاز أثناء الجولة ثم أعيدوه بنفس المتصفح. جرّبوا أيضًا المرور بجوال واحد، وإخفاء الشاشة بين كل شخصين، وصورة بطاقات الجريمة على جوال فعلي.

اختباراتنا المحلية لا تثبت إعداد مشروع Supabase المستضاف أو عمل Realtime عبر شبكة أجهزتكم. دعم المشاركة الأصلية على iOS/Android يحتاج تجربة الجهاز نفسه؛ فحص المتصفح يثبت توليد PNG وتنزيله. جلسة الجوال الواحد تحفظ بياناتها في التبويب، وتعتمد خصوصيتها على تمرير الجهاز بأمانة؛ بيانات اللعبة المحلية متاحة لمالك الجهاز من أدوات المتصفح.

## تشغيل الفحوص مرة أخرى

استخدم Node.js 24، أو 22.18 فأحدث:

```bash
npm ci
npm test
npm run build
```

لفحص المتصفح مع قاعدة بيانات اختبار معزولة:

```bash
npx playwright install chromium --only-shell
npm run test:browser
```

الأمر الأخير يبني نسخة اختبار بمفتاح وهمي، ويشغّل Next على `127.0.0.1:3035` وخادم الاختبار على `127.0.0.1:54329`. يلزم أن يكون المنفذان متاحين. النتائج والصور في `test-results`؛ لا ترفعها إلى الموقع. يمكن اختيار متصفح مثبت عبر `FATIN_BROWSER=msedge` في البيئة إذا كان مسموح التشغيل. مجلدات `.next-test-*` نواتج اختبار فقط، ولا تدخل حزمة النشر.

فحص قاعدة البيانات ينفّذ SQL الفعلي على PostgreSQL عبر PGlite بهويات اختبار. محوّل المتصفح المحلي لا ينفّذ GoTrue أو WebSocket Realtime؛ التحديث بين المتصفحات يختبر مسار التحديث الدوري الاحتياطي. لا تُستخدم مفاتيح Supabase الفعلية في هذه الفحوص.
