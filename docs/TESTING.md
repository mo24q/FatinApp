# سجل التحقق

## نسخة التجربة v8 — ٢٢ أكتوبر ٢٠٢٦

- **٧٧ اختبارًا ناجحًا، صفر فشل:** قواعد اللعب المحلي، SQL للألعاب الست، صلاحيات المضيف والراوي، عدم وصول الأسرار لغير صاحبها، النقاط والتصويت، المؤقتات، الجولات المتكررة، وحفظ الجلسة.
- اختبارات SQL تشغّل ملفات 001–008 وبنك المحتوى على PostgreSQL عبر PGlite. جُرّبت ترقية قاعدة عند 003 مباشرة إلى 008، ثم تكرار 008 مع جلسات للألعاب الست وأسئلة مخصصة؛ لم تضِع البيانات.
- **١٤ سيناريو متصفح ناجحًا، دون أخطاء JavaScript غير معالجة** على Chromium Headless Shell 151: قائمة الألعاب وصفحات الدخول، وجولات محلية للألعاب الست، وإنشاء/انضمام من متصفحين مستقلين واستعادة الاتصال، وواجهة أونلاين خاصة لكل لعبة.
- اللعب المحلي شمل المرور الإجباري بين الأدوار، إعادة التحميل وإخفاء الأسرار، اكتمال الإجابات قبل كشفها، حساب النقاط، دورتَي توزيع الأدوار والليل في المافيا، التخطي، إكمال الموجة، الحروف والتراجع، والجريمة مع اختيار السلاح والدليل والراوي والإعادة.
- صور الصفحة الرئيسية بعروض 320 و390 و1280 بكسل، وبقية صفحات الدخول بعرض 320، ومشاهد الألعاب بعرض 390: لا تمرير أفقي في الفحوص. فُحصت لقطات ليل المافيا وبطاقات الجريمة ونتيجة السؤال المغلوط بصريًا.
- توليد صورة البطاقات العامة وتنزيل PNG بحجم 1080×1500 نجح، دون فتح معاينة الصورة داخل الموقع.
- **بناء إنتاج وفحص TypeScript ناجحان** باستخدام Next.js 16.4.2 مع webpack وNode.js 24.19.0. في هذه البيئة المقيدة، تعثرت بعض عمليات البناء بصلاحية EPERM لملفات الكاش، وتشغيل Edge انتهى قبل الفحص. اكتمل التحقق باستدعاء البناء مباشرة في مجلد مستقل وتشغيل Chromium المخصص للاختبار. لم تُغيَّر طريقة بناء Vercel الافتراضية.
- التحقق من المصدر العام أعاد الالتزام `a8ad2a38d0fd05756655bf2a7457c4617642e262`؛ منه صُنعت حزمة الملفات المتغيرة. لم يُرفع المصدر إلى GitHub أو Vercel ولم يُطبّق SQL في حساب المستخدم.

حدود التحقق: هويات Auth محاكاة اختبار، وRealtime المستضاف غير متاح في خادم الفحص. تزامن المتصفحين اختبر التحديث الدوري الاحتياطي الذي يستخدمه الموقع عند غياب Realtime. لا يغطي هذا اختبارات أحمال كبيرة أو أجهزة iPhone/Android فعلية أو مشاركة الملفات الأصلية فيها. خطوات تجربة الأجهزة بعد النشر في [دليل 008](READINESS.md).

لتكرار الفحوص: `npm test`، ثم `npm run test:browser` بعد تثبيت متصفح Playwright كما في الدليل. خادم الاختبار يستمع على loopback فقط ويستخدم قاعدة مؤقتة؛ لا يتصل بقاعدة المستخدم.

## تحديث ٢٠ أكتوبر ٢٠٢٦ — المؤقت والجوال الواحد

- `npm test`: ٣١ اختبارًا ناجحًا: ٢٤ لقواعد SQL والصلاحيات والتحديث و٧ لمنطق الجوال الواحد.
- ترقية 001 إلى 002 مع جولة نشطة ودور وصوت موجودين، وإعادة تشغيل 002: ناجحتان دون فقد البيانات.
- منع غير الأعضاء وغير المضيف من أوامر الوقت، حماية رقم الجولة والمرحلة، رفض تمديد التصويت المنتهي، ونقل تحكم الوقت مع الاستضافة: ناجح.
- إلغاء المؤقت والإيقاف المؤقت وتغيير المدة والاستئناف وإعادة الوقت، مع استمرار قبول الأصوات وحسمها: ناجح.
- اللعب المحلي: أسماء صالحة وفريدة، تمرير الأدوار بالتسلسل، منع التصويت للنفس، نتيجة التعادل، وتغيير الكلمة والدور في الإعادة: ناجح.
- الاستعادة من بيانات جلسة محلية صالحة، ورفض البيانات المعطوبة والمنتهية: ناجح. حالة إظهار الدور ليست جزءًا من الحالة المحفوظة.
- `npm run typecheck`: ناجح.
- `npm run build -- --webpack`: بناء إنتاج ناجح، مع `/` و`/local` و`/room/[code]`. البناء الافتراضي بـTurbopack تعذّر هنا بسبب منع اتصال عملية معالجة CSS الفرعية داخل بيئة Windows المقيدة، وليس خطأ TypeScript أو CSS مثبتًا. لم تتغير إعدادات بناء Vercel بسبب هذا القيد المحلي.
- فُحص بناء الإنتاج بالمتصفح بعد السماح بالاتصال المحلي: اختيار جوال واحد من الرئيسية، ثلاثة لاعبين، دور عشوائي واحد والكلمة نفسها للبقية، إخفاء الدور بين اللاعبين وبعد تحديث الصفحة، ثم النقاش والتصويت والكشف بنتيجة وأصوات صحيحة. الإعادة غيّرت الكلمة وصاحب الدور، وإلغاء الجولة أعاد الأسماء.
- جُرّبت أزرار الإيقاف والاستئناف والإلغاء والتشغيل وإعادة الوقت وتطبيق ٤٥ ثانية مع الحفاظ على الإيقاف. فُحص عرضا ٣٩٠ و٣٢٠ بكسل دون تمرير أفقي، ولم تظهر أخطاء أو تحذيرات في سجل المتصفح. كشف الفحص حالة عرض مدة مخصصة في نموذج الأسماء؛ أُضيف لها خيار يطابق المدة الفعلية.
- بعد التصحيح أُعيد بناء الإنتاج بنجاح في مجلد تحقق مستقل لتجاوز تعارض صلاحيات ملفات البناء المحلية القديمة. فُحصت النسخة الناتجة بالمتصفح، وظهر خيار «٤٥ ثانية (مدتكم الحالية)» بعد العودة للأسماء. أُعيدت إعدادات البناء الأصلية قبل تغليف الملفات.
- قورنت ملفات الحزمة الأصلية مع مستودع `mo24q/FatinApp` عند الالتزام `3d05d1088634b2f0c65eca104efd45245aa3ae7e`: ملفات التطبيق متطابقة؛ الملفان المخفيان `.gitignore` و`.env.example` غير موجودين في الرفع السابق، وتحتوي عليهما حزمة التحديث. لا تستبدل الحزمة ملفات إضافية مثل LICENSE.
- لم يُرفع هذا التحديث إلى GitHub/Vercel ولم يُطبّق 002 في Supabase المستضاف. يلزم اختبار ثلاثة أجهزة بعد تطبيق الملف والنشر؛ PGlite يحاكي Auth ولا يثبت Realtime المستضاف.

## تم التحقق

| الفحص | النتيجة |
|---|---|
| `npm install` | تم تثبيت الحزم وتثبيتها في `package-lock.json`؛ فحص npm وقت التثبيت لم يسجل ثغرات معروفة. |
| `npm test` | ١٧ اختبارًا ناجحًا على PGlite 0.3.16، تنفيذًا لملف SQL نفسه. |
| `npm run build` | بناء إنتاج ناجح على Next.js 16.4.2، مع فحص TypeScript وتوليد الصفحات. |
| طلب HTTP للرئيسية | استجابة 200 من خادم Next.js المحلي. |
| متصفح سطح المكتب | فحص بصري للرئيسية وقائمة الألعاب. لا رسائل خطأ/تحذير في سجل المتصفح عند الفحص. |
| عرض ٣٩٠ و٣٢٠ بكسل | فحص الواجهة العربية وعدم وجود تمرير أفقي بعد إصلاح الحد الأدنى لعرض شبكة المقدمة. |
| نافذتا إنشاء/انضمام | التركيز ينتقل إلى الاسم، إغلاق النافذة يعمل، اختيار مدة النقاش ظاهر، والرمز يُحوّل إلى أحرف كبيرة. |
| عدم وجود إعدادات Supabase | إنشاء الغرفة معطّل مع رسالة واضحة؛ رابط غرفة مباشر يوضح الحاجة للإعداد. |

إصدارات بيئة التحقق: Node.js 24.16.0، React 19.3.1، TypeScript 5.9.3، Tailwind 4.3.3، Supabase JS 2.118.0.

## تغطية اختبارات قاعدة البيانات

1. رمز قصير، إنشاء وانضمام، وهوية ثابتة عند العودة.
2. رفض مفتاح `anon` بلا جلسة ورفض هوية JWT الفارغة.
3. الاسم، مدة النقاش، والحد الأدنى للاعبين.
4. الاسم المكرر، الانضمام المتأخر، وإعادة الاتصال خلال الجولة.
5. لاعب واحد برا السالفة، كلمة موحدة للبقية، وغياب الأسرار عن استجابة الحالة.
6. منع غير الأعضاء من الحالة والدور وأوامر اللعب حتى مع معرفة الرمز.
7. صلاحيات المضيف، حاجز جاهزية الجميع، ورفض رقم الجولة القديم.
8. صوت واحد نهائي، منع التصويت للنفس أو للاعب خارجي، وخصوصية الاختيارات.
9. حسم فوز المجموعة وكشف النتيجة بعد اكتمال الأصوات.
10. التعادل، غياب الأصوات، وحسم المهلة من قراءة عضو.
11. كلمة ودور مختلفان في الإعادة، وعدم وصول صوت قديم لجولة جديدة.
12. الحضور، منع البدء مع غائب، ونقل الاستضافة بعد دقيقة.
13. إلغاء الجولة دون كشف الأسرار، وإزالة العضوية بين الجولات فقط.
14. RLS لإشعارات Realtime، ومنع قراءة كل الجداول والدوال السرية مباشرة.
15. الحد ١٢ لاعبًا، انتهاء صلاحية الغرفة، والتنظيف.
16. المغادرة ونقل الاستضافة وسحب صلاحية العضو السابق.
17. حصة إنشاء الغرف تبقى نافذة بعد مغادرة/حذف الغرف، وتجدد بعد ساعة.

## إضافة الجريمة المغلقة — ٢٠ أكتوبر ٢٠٢٦

- مجموع الاختبارات الآلية: ٥٥ ناجحة؛ منها ١٥ لاختبار قاعدة بيانات الجريمة و٩ لمحرك الجوال الواحد، مع بقاء ٣١ اختبارًا سابقًا ناجحًا.
- ملف التحديث المجمع اختُبر بعد 001 مباشرة، ثم اختُبر تكراره مرتين مع قضية نشطة دون تغيير الدور أو الحل أو فقد توجيه اللعبة السابقة.
- اختبار المتصفح المحلي شمل توزيع الأدوار وتمرير الهاتف، اختيار السلاح والدليل، وصول الحل إلى الراوي، إخفاء الملف بعد إعادة تحميل الصفحة، تعديل التلميحات، اتهامًا صحيحًا انتهى بفوز المحققين، وبدء قضية ثانية. نسخ رابط البطاقات وفتحه في تبويب مستقل أظهر البطاقات الثماني دون دور أو حل.
- ظهر ترتيب ٤ أسلحة يمينًا و٤ أدلة يسارًا على عرضي 390px و320px دون تجاوز أفقي. لم تظهر أخطاء في سجل المتصفح أثناء الجولة.
- بناء الإنتاج `next build --webpack` وفحص TypeScript نجحا على نسخة مطابقة للمصدر في مسار تحقق قصير. حدث خطأ Windows EPERM في مجلدات البناء بالمسار الأصلي؛ لم تُضف إعدادات التفاف إلى الحزمة المنشورة.

## حدود التحقق

لا توجد بيانات مشروع Supabase أو Vercel في البيئة؛ لذلك لم يُنشأ نشر خارجي ولم تُختبر دورة لعب من عدة جوالات عبر Auth وRealtime الحقيقيين، ولا تكامل Turnstile الفعلي. مراحل الغرف اختُبرت على مستوى قاعدة البيانات؛ الفحص البصري محلي كما هو موضح أعلاه.

PGlite يشغّل PostgreSQL داخل عملية الاختبار مع `auth.uid()` محاكى؛ لا يختبر توقيع JWT لدى GoTrue، أو خدمة Realtime، أو بيئة تحميل متزامن حقيقية. أقفال صف الغرفة مفروضة في SQL، لكن اختبار ضغط على PostgreSQL المستضاف مطلوب قبل توسيع الاستخدام.

خادم التطوير المحلي مؤقت. أعد تشغيل `npm run dev` عند الحاجة. اتبع قائمة القبول في README بعد وضع المفاتيح وتطبيق الترحيل، ثم اختبر الرابط المنشور على ثلاثة أجهزة مستقلة.
