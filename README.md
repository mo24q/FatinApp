# فطين — ألعاب تجمعنا

**تحديث المؤقت والجوال الواحد:** للموقع الذي يعمل بالفعل، اتبع [دليل التحديث](docs/UPDATE-2026-10-20.md). شغّل `002_host_timer.sql` فقط، ثم ارفع الكود. لا تعِد تشغيل ملف التهيئة الأول على قاعدة البيانات الحالية.

المستودع المستهدف: [mo24q/FatinApp](https://github.com/mo24q/FatinApp)، المرتبط مسبقًا بـVercel حسب صاحب المشروع. هذه نسخة جديدة مستقلة؛ لم يُنسخ أي كود من النسخة القديمة. لتحديث المشروع المرتبط بدل إنشاء مشروع جديد، اتبع [دليل الانتقال](docs/EXISTING-VERCEL.md).

بداية منصة ألعاب جماعية بالعربية وRTL. أول لعبة مكتملة: **برا السالفة**، لـ٣–١٢ لاعبًا، بلا بريد أو كلمة مرور. اختر غرفة لكل لاعب بجواله، أو وضع «جوال واحد» لتمرير الجهاز بين اللاعبين. المضيف يشارك باللعب.

المشروع يستخدم **Next.js App Router + React + TypeScript + Tailwind CSS + Supabase Auth/Postgres/Realtime**. خادم قواعد اللعبة هو PostgreSQL عبر دوال RPC؛ لا يعتمد على ذاكرة خادم Next.js أو WebSocket على Vercel. قائمة الألعاب قابلة للتوسعة، والبطاقتان «قريبًا» ليستا لعبتين منفذتين.

## ابدأ من هنا

الغرف تحتاج مشروع Supabase وحساب Vercel للنشر. بدون مفاتيح يبقى إنشاء الغرف معطّلًا، لكن وضع «جوال واحد» في `/local` يعمل مستقلًا ببيانات داخل التبويب فقط، دون إرسالها إلى Supabase.

1. جهّز Supabase بالخطوات التالية.
2. انسخ `.env.example` إلى `.env.local` وأدخل رابط المشروع والمفتاح العام.
3. داخل مجلد المشروع شغّل:

```bash
npm ci
npm run dev
```

افتح `http://localhost:3000`. استخدم Node.js 24؛ اختبارات اللعب المحلي تقرأ TypeScript مباشرة باستخدام دعمه المدمج. في PowerShell إذا منعت سياسة التنفيذ `npm`، استخدم `npm.cmd`.

```powershell
Copy-Item .env.example .env.local
```

## ربط قاعدة البيانات

### ١. إنشاء مشروع جديد

من [لوحة Supabase](https://supabase.com/dashboard) أنشئ مشروعًا، وانتظر جاهزية قاعدة البيانات. استخدم مشروعًا مخصصًا لهذه النسخة. ملف التهيئة يُطبَّق مرة واحدة ولا يحذف جداول موجودة.

### ٢. تشغيل ملف SQL

افتح SQL Editor، ثم انسخ **كامل** محتوى `supabase/migrations/001_lamma.sql` وشغّله. الملف ينشئ:

- مخطط `private` للجداول السرية: الغرف، اللاعبين، الكلمات، الأدوار، الجاهزية، الأصوات وحد إنشاء الغرف.
- دالة `public.game_action` لكل أوامر اللعبة، ودالة للتحقق من عضوية الغرفة.
- جدول `public.room_events` يحتوي **معرّف الغرفة ورقم تحديث فقط**، مع سياسة RLS للأعضاء.
- ٤٠ كلمة يومية أصلية موزعة على خمس فئات.
- ربط `room_events` بمنشور `supabase_realtime` إذا كان موجودًا، كما هو الحال في مشاريع Supabase.

بعد نجاحه في المشروع الجديد، شغّل `supabase/migrations/002_host_timer.sql` لإضافة أدوات المؤقت. أما المشروع الذي سبق تهيئته فيحتاج 002 فقط.

لا تضف `private` إلى Exposed schemas. أبقِ الأسرار خارج الجداول العامة، ولا تمنح `anon` أو `authenticated` صلاحيات مباشرة عليها.

تأكد في إعدادات Realtime/Replication من تفعيل `public.room_events` فقط. للتحقق عبر SQL:

```sql
select schemaname, tablename
from pg_publication_tables
where pubname = 'supabase_realtime';
```

ينبغي أن يظهر `public.room_events`. إذا لم يظهر، شغّل مرة واحدة:

```sql
alter publication supabase_realtime add table public.room_events;
```

### ٣. تفعيل الضيوف

في Authentication → Sign In / Providers فعّل **Allow anonymous sign-ins**. هؤلاء ضيوف بهويات داخلية موقّعة؛ لا يُطلب منهم التسجيل. تختلف جلسة الضيف عن مفتاح `anon` العام. [توثيق Supabase](https://supabase.com/docs/guides/auth/auth-anonymous).

تُحفظ جلسة Supabase في متصفح اللاعب. إعادة تحميل الصفحة أو انقطاع الإنترنت لا ينشئ لاعبًا جديدًا. حذف بيانات المتصفح أو استخدام جهاز آخر لا يستعيد الهوية القديمة؛ يمكن للمضيف إلغاء الجولة وإزالة المقعد القديم ثم انضمام اللاعب من جديد.

### ٤. المفاتيح المطلوبة

من إعدادات المشروع انسخ Project URL و**Publishable key**، أو مفتاح `anon` القديم إذا كان هذا هو المتاح:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
NEXT_PUBLIC_TURNSTILE_SITE_KEY=
```

المفتاحان الأولان مطلوبان. متغير Turnstile اختياري. **لا تحتاج `service_role`، أو Secret API key، أو كلمة مرور قاعدة البيانات في التطبيق**. لا تضع أيًا منها في متغير يبدأ بـ`NEXT_PUBLIC_`.

المتغيرات العامة تُضمّن وقت البناء؛ بعد تعديلها أعد تشغيل التطوير أو أعد النشر على Vercel. [توثيق Next.js](https://nextjs.org/docs/app/guides/environment-variables).

### ٥. حماية دخول الضيوف عند فتح الموقع للعموم

للموقع العام، فعّل Cloudflare Turnstile من Supabase Auth → Bot and Abuse Protection. ضع **المفتاح السري لـTurnstile في لوحة Supabase فقط**، وضع مفتاح الموقع العام في `NEXT_PUBLIC_TURNSTILE_SITE_KEY`. أضف نطاق Vercel الفعلي ونطاقك إلى إعدادات Turnstile. نموذج الدخول يدعم الودجت ويرسل رمزه إلى Supabase Auth.

Supabase يوصي بـCAPTCHA لدخول الضيوف. الحد الافتراضي لإنشاء الضيوف هو ٣٠ طلبًا في الساعة لكل IP؛ يمكن تغييره من اللوحة. هذا يهم عند وجود عدة جوالات على شبكة منزلية واحدة. الجلسات المحفوظة لا تعيد إنشاء الضيف عند كل جولة. [حماية CAPTCHA](https://supabase.com/docs/guides/auth/auth-captcha)، [حدود الطلبات](https://supabase.com/docs/guides/auth/rate-limits).

## النشر على Vercel

1. ارفع محتويات هذا المجلد إلى مستودع Git خاص بك، مع `package-lock.json`، واستبعد `node_modules` و`.next` و`.env.local` كما يحدد `.gitignore`.
2. من Vercel اختر Add New → Project واستورد المستودع.
3. اختر Framework Preset: **Next.js**. إذا رفعت مجلدًا يحتوي هذا المشروع، اضبط Root Directory على المجلد الذي يحتوي `package.json`.
4. استخدم Node.js **24.x**، وأمر تثبيت `npm ci` وأمر بناء `npm run build`. اترك Output Directory الافتراضي.
5. أضف متغيري Supabase السابقين إلى Production وPreview. أضف مفتاح Turnstile العام إذا فعّلته. يفضّل مشروع Supabase منفصل للاختبارات عن بيانات الاستخدام الحقيقي.
6. انشر المشروع. من Supabase Auth → URL Configuration ضع رابط الموقع النهائي في Site URL. لا يحتاج هذا التدفق OAuth redirect أو بريدًا.
7. اختبر الرابط المنشور باستخدام ثلاث جلسات مستقلة. إعادة تبويب نفس المتصفح تشارك هوية الضيف؛ استخدم ثلاثة أجهزة أو ملفات تعريف متصفح مستقلة.

لا يحتاج هذا المشروع `vercel.json` أو اتصال PostgreSQL مباشر أو منفذ WebSocket على Vercel. المتصفح يتصل بخدمات Supabase مباشرة؛ الصلاحيات تُطبّق هناك. [متغيرات Vercel](https://vercel.com/docs/environment-variables)، [النشر من CLI](https://vercel.com/docs/projects/deploy-from-cli).

بديل CLI من داخل مجلد المشروع، بعد تثبيت Vercel CLI وتسجيل الدخول:

```bash
vercel
vercel --prod
```

## كيف تلعبون؟

1. المضيف ينشئ غرفة ويحدد مدة النقاش: ١، ٢، ٣، أو ٥ دقائق.
2. يشارك رمزًا من ستة أحرف/أرقام أو رابط الدعوة. يدخل اللاعبون بأسماء مختلفة، وعددهم ٣–١٢.
3. يبدأ المضيف عندما يكون الجميع متصلين. تختار قاعدة البيانات كلمة واحدة ولاعبًا واحدًا «برا السالفة».
4. كل لاعب يفتح دوره بنفسه ويؤكد الجاهزية. الفئة معروفة للجميع، أما الكلمة فلا تصل للاعب «برا السالفة».
5. يبدأ المضيف النقاش بعد جاهزية الجميع. المؤقت إرشادي؛ المضيف يفتح التصويت عندما يقرر، حتى قبل انتهاء النقاش.
6. التصويت مدته الافتراضية دقيقة، ويستطيع المضيف تغييرها أو إيقافها أو إلغاء المؤقت. لا تصويت للنفس، ولا تغيير بعد تثبيت الصوت. عند تصويت الجميع تظهر النتيجة؛ وعند انتهاء الوقت يحسم أول تحديث من أي عضو النتيجة تلقائيًا.
7. إذا انفرد «برا السالفة» بأعلى عدد أصوات، يفوز بقية اللاعبين. في التعادل أو غياب الأصوات أو اختيار لاعب آخر، يفوز «برا السالفة». تظهر الكلمة وهويته وعدد الأصوات لكل لاعب، دون نشر اختيارات الأفراد.
8. المضيف يعيد اللعب بكلمة مختلفة، ولاعب مختلف «برا السالفة» عن الجولة السابقة. ينضم اللاعبون الجدد فقط في اللوبي أو شاشة النتيجة.

## الانقطاع وإدارة الغرفة

- يوجد Realtime، مع قراءة احتياطية كل ٥ ثوانٍ عندما الصفحة ظاهرة. إذا تعطلت القناة الفورية تستمر اللعبة عبر التحديث الدوري.
- كل قراءة موثقة تجدد حضور اللاعب. يُعرض غير متصل بعد ٦٠ ثانية من غيابه؛ تبويبات الخلفية وقفل الجوال قد تجعل اللاعب يبدو غائبًا.
- بعد غياب المضيف ٦٠ ثانية، يستطيع عضو متصل الضغط على «استلام الاستضافة». قاعدة البيانات تتحقق من الغياب وتمنع التضارب؛ أول طلب ناجح يصبح المضيف.
- لا تُحذف الأدوار عند الانقطاع. لإصلاح جولة عالقة، يستطيع المضيف إلغاءها دون كشف الكلمة، ثم إزالة الغائب في اللوبي وإعادة البدء. في التصويت، المهلة تحسم حتى إن غاب لاعب.
- إزالة لاعب تلغي عضويته الحالية، وليست حظرًا دائمًا؛ يستطيع الانضمام مجددًا إذا عرف الرمز وكانت الغرفة في مرحلة تسمح بالدخول.
- الغرفة تنتهي بعد ٢٤ ساعة. الأدوار القديمة لا تتاح عبر أي أمر عام.
- تعطيل الأزرار وإخفاء الدور في الواجهة وسائل راحة فقط. الأمان الفعلي من JWT وRLS والتحقق داخل SQL.

## الاختبارات

```bash
npm test
npm run typecheck
npm run build
```

الاختبارات تنفذ **ملف SQL الفعلي** على PostgreSQL عبر PGlite، مع محاكاة `auth.uid()` وأدوار `anon` و`authenticated`. لا تتطلب مفاتيح ولا تمس قاعدة بيانات حقيقية. تغطي الأدوار والسرية وRLS، صلاحيات المضيف، انتقالات المراحل، التصويت والمهلة والتعادل، إعادة اللعب، الاستعادة ونقل الاستضافة، الحد الأقصى للاعبين، انتهاء الغرف، وحصة إنشاء الغرف.

نتيجة التحقق موثقة في `docs/TESTING.md`. تشغيل Auth وRealtime الحقيقيين وثلاثة جوالات يحتاج إتمام الربط؛ محاكاة SQL لا تثبت إعداد خدمة Realtime أو سياسة Auth في مشروعك.

### اختبار قبول بعد الربط

- أنشئ غرفة من جهاز A، وانضم من B وC. تحقق من ظهور الجميع دون تحديث يدوي.
- شغّل جولة. تحقق من أن هناك لاعبًا واحدًا بلا كلمة، وأن الآخرين يرون الكلمة نفسها، ولا تظهر أدوارهم في استجابة `state`.
- أكد الجاهزية، افتح النقاش والتصويت، وصوّت. اختبر دورة أخرى وتحقق من تغيّر الكلمة واللاعب «برا السالفة».
- أعد تحميل B أثناء الجولة: يجب أن يحتفظ بالاسم والدور. افصل الشبكة وأعدها: يعود تحديث الغرفة.
- أغلق شاشة A أكثر من دقيقة، واستلم الاستضافة من B. جرّب إلغاء الجولة وإزالة مقعد غائب.
- بعد فتح التصويت امتنع عن التصويت وانتظر دقيقة: يجب ظهور النتيجة عند التحديث التالي.
- احجب WebSocket في أدوات المطور مؤقتًا: يجب استمرار التحديث كل ٥ ثوانٍ. اختبر على الجوال بأسماء عربية طويلة.
- بعد تفعيل Turnstile، اختبر انضمام ضيف جديد من جلسة جديدة على النطاق النهائي.

## بنية المشروع والتوسعة

```text
src/app/                  صفحات Next.js وRTL والتصميم
src/components/home.tsx   الرئيسية، القائمة، إنشاء/انضمام
src/components/room.tsx   اللوبي ومراحل اللعب والاتصال
src/components/captcha.tsx التحقق الاختياري
src/lib/games.ts          كتالوج الألعاب
src/lib/supabase.ts       جلسة الضيف وأوامر RPC والأخطاء العربية
src/lib/types.ts          البيانات العامة المسموح بها والدور الخاص
supabase/migrations/     قواعد اللعبة والصلاحيات وبنك الكلمات
tests/game.test.mjs       اختبارات SQL على PostgreSQL محلي
docs/SECURITY.md          حدود الثقة وقواعد الأمان
docs/TESTING.md           سجل التحقق وحدوده
```

إضافة بطاقة إلى `games.ts` توسّع الكتالوج. عند تنفيذ لعبة أخرى أضف مسارها وقواعدها ودوالها الخاصة، ثم اجعل البطاقة متاحة واربط الزر بها. لا يكفي تغيير `available` وحده؛ النسخة الحالية تنفذ لعبة برا السالفة فقط. لفصل عدة ألعاب في غرف مشتركة مستقبلًا، أضف `game_id` إلى الغرفة مع ترحيل جديد؛ لا تعدّل ملف التهيئة الذي طُبّق على إنتاج موجود.

لإضافة كلمة، استخدم SQL Editor بحساب مالك قاعدة البيانات:

```sql
insert into private.words(category,word) values ('أماكن','حديقة');
```

### تنظيف البيانات

أنشئ مهمة Supabase Cron يومية تشغّل:

```sql
select private.cleanup_expired_rooms();
```

تزيل الغرف المنتهية وسجلاتها التابعة. لا تنظف هذه الدالة مستخدمي Auth؛ عالج حسابات الضيوف القديمة بشكل منفصل وفق سياسة الاحتفاظ الخاصة بك، مع تجنب المستخدمين ذوي الغرف النشطة. لا تشغّل وظائف التنظيف عبر المفتاح العام.

## الأصول

العلامة والرسوم والشخصيات صُممت بالكود لهذا المشروع. بنك الكلمات عبارة عن مفردات يومية أصلية، وليس منسوخًا من بطاقات أو قوائم لعبة تجارية. الأيقونات من Lucide (ISC)، والخط Noto Sans Arabic (SIL Open Font License)، والملفات تُقدَّم محليًا من الحزم. الاسم «برا السالفة» هنا يصف نمط اللعب المطلوب؛ لا يتضمن المشروع شعارًا أو هوية أو أصولًا لمنتج تجاري.
